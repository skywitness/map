地圖可以切換地球儀與平面、一路放大到街道，並有五種底圖配色可選。按「3D」可以把數值畫成高度：比率類指標把國家依色階分級拉高，總量類指標畫成高度與數值成正比的柱子，可以旋轉、傾斜；海拔主題的 3D 是真的立體地形（地球儀上也可以）。人口主題可以在地圖上框選範圍，估算框內人口；「人口密度」可以從國家平均切到「1 km 網格」，看每個約 1 km 的格子住多少人（JRC GHS-POP，1975–2030 每 5 年一期，跟著時間軸換期）；氣溫與降雨主題的「暖化」也可以切到「0.5° 網格」，看國內各地比 1951–1980 年熱了多少（CRU TS，每年一期）；太陽能與風能潛力也可以切到「約 2 km 網格」（Global Solar Atlas、Global Wind Atlas）；夜間燈光一打開就是「約 500 m 網格」（EOG 的 VIIRS 年度合成，2013、2016、2020、2024 四期），網格底下鋪一層夜色，任何底圖上都是夜景；航運與港口的「航運密度」是約 5 km 的網格（世界銀行與 IMF 用 2015–2021 年的 AIS 船位算出），看得到全球的航道。

每個畫面右上角的「分享」可以下載地圖圖片（PNG，含標題、圖例與資料來源）、下載目前指標的 CSV（選定年份或所有年份，Excel 可直接開啟），或複製這個畫面的連結。

右上角的「中文 / EN」切換介面語言，不必重新整理；英文版的網址帶 `lang=en`，分享出去打開就是英文。

## 操作

- **搜尋國家**：中文、英文、常用別名（南韓、韓國、Korea；美國、USA；英國、UK；中國、大陸）或 ISO 代碼（TW、TWN）都找得到，打一部分或拼錯一兩個字母也可以。結果會列出目前的數值，選了之後地圖會飛到那個國家。
- **鍵盤快捷鍵**（按 `?` 或右上角的「?」看說明）：
  - `/`：搜尋
  - `←` `→`：換年份（海拔這類不隨時間變化的資料沒有時間軸）
  - 空白鍵：播放／暫停
  - `+` `−`：縮放地圖
  - `Esc`：取消選取
- **手機**：國家資料從底部抽屜拉起，可以拖到收合、半開、全開三段，往下拖到底就關閉。
- **語言**：「中文 / EN」切換，選擇記在瀏覽器裡；英文版的數字用 K、M、B、T（中文用萬、億、兆），國名與地圖上的地名也換成英文。

看過一次之後，再開啟會直接從瀏覽器的快取載入，沒有網路也能開（標題旁會顯示「離線中」，資料與地圖是上次看過的部分）。手機與桌機的瀏覽器都可以把它安裝成 App。載入速度的量測與做法見 DESIGN.md 第 13 節。

網站：https://skywitness.github.io/map/

## 開發

```bash
npm install
npm run dev
```

`public/data/` 裡已經有產生好的資料，只改前端的話不需要跑資料管線。

### 檢查英文版

```bash
npm run check:i18n
```

掃描 `src/` 的原始碼，列出英文介面會看到、卻還沒翻譯的中文（新增功能或主題後跑一次）。

```bash
npm i --no-save puppeteer-core
npm run check:en
```

用無頭 Chrome 打開英文版，細看指定的主題（每個指標、排名表、國家側欄），列出畫面上剩下的中文，也檢查中英切換與 `lang=en` 的網址。需要系統的 Chrome（或設定 `CHROME_PATH`）。一律指定主題：

```bash
CHECK_TOPICS=antipodes npm run check:en
```

其他主題照樣依序點過（換主題時的錯誤抓得到），只是不逐一換指標、開側欄。沒有指定時不跑；每個主題都細看的完整檢查（15 分鐘到 1 小時以上）只在特別要求時跑：`CHECK_ALL=1 npm run check:en`（DESIGN.md 第 12 節）。

`population-grid` 是框選估算用的網格人口，`elevation` 是海拔主題（USGS GMTED2010 的 1 公里 DEM，第一次會下載約 760 MB），兩個都要先有 `geo` 的國界。`disease` 第一次會向 WHO 的 API 一年一年查 2000–2023 年的死因資料，約 15 分鐘。`migration` 第一次會向 UNHCR 的 API 一年一年查 1990 年以來的難民資料，約 2 分鐘。`inequality` 第一次會下載 World Inequality Database 的整包資料（約 890 MB），`wealth` 共用同一份。

`population-density-tiles` 產生人口密度的 1 km 網格圖磚（`public/tiles/`，約 585 MB、6 萬個檔）。圖磚不進版本控制，部署時由 GitHub Actions 產生；本機要看網格才需要跑，第一次會下載 12 期 GHS-POP（共 5.8 GB），約 25 分鐘。沒跑的話，切到「1 km 網格」會顯示載入失敗、改畫國家平均。開發伺服器不監看 `public/tiles/`（檔案太多會卡住），所以產生圖磚之後要重開 `npm run dev`。做法與大小見 DESIGN.md 第 14 節。

`submarine-cables` 第一次會向 TeleGeography 的 API 一條一條抓 713 條電纜的明細（每次間隔 0.4 秒，約 18 分鐘、共約 1.6 MB），之後用快取；要更新加 `--refresh`。

`temperature` 是氣溫與降雨主題（CRU TS，第一次會下載月均溫與降雨約 385 MB）。`temperature-grid-tiles` 產生暖化的 0.5° 網格圖磚（`public/tiles/warming/`，約 20 MB、2.4 萬個檔），跟人口密度的網格一樣不進版本控制、部署時產生，本機約 3–5 分鐘。

`typhoons` 是颱風與颶風主題（NOAA IBTrACS，333 MB；NCEI 單一連線很慢，見 DESIGN.md 第 8 節第 58 點）。`power-plants` 下載 Global Energy Monitor 公開地圖的資料檔（約 62 MB）。`fossil-fuels` 下載 EIA 的 International Energy Statistics（24 MB）、GEM 四個 tracker 的公開地圖檔（約 430 MB）與 CEPII BACI HS92（2.4 GB，跟 `plastic` 共用；第一次讀約 4 分鐘，燃料的部分另存在快取）；經濟部能源署的進口來源在 cloud 會被 Cloudflare 擋，要先把檔案放進 `pipeline/.cache/moeaea/`（見 DESIGN.md 第 8 節第 12 點）。`renewables` 是太陽能與風能潛力的各國平均，`renewables-grid-tiles` 產生它的約 2 km 網格圖磚（`public/tiles/renewables-solar/`、`renewables-wind/`，約 9 MB、1,150 個檔，部署時產生）；兩個都要下載 Global Solar Atlas 的 PVOUT（345 MB）與 Global Wind Atlas 檔案裡 0.02° 的縮小版（182 MB，只抓那一段），本機約 2–3 分鐘。`wildfires` 下載 GWIS 的燒毀面積（約 12 MB），第一次另外向 GWIS 查各國面積，約 6 分鐘。

`night-lights` 是夜間燈光主題的各國統計與燈光最多的地區：第一次會從 Zenodo 下載 2013–2024 年的 VIIRS 夜間燈光（EOG Annual VNL V2 的轉存，12 個檔、共約 820 MB；Zenodo 慢的時候每條連線只有約 25 KB/s，分段平行下載，最慢約 20 分鐘），人口用 GHS-POP 2015、2020、2025 三期（跟 `population-density-tiles` 共用快取），另外下載 Natural Earth 的第一級行政區（約 41 MB），要先有 `geo` 的國界，統計約 7 分鐘（算完存在快取，只改輸出時幾秒）。`night-lights-tiles` 產生它的約 500 m 網格圖磚（`public/tiles/night-lights/`，4 期、約 106 MB、2.1 萬個檔，部署時產生），本機約 2.5 分鐘。

`house-prices` 是房價與居住負擔主題：下載 OECD 的房價指標（約 17 MB）、BIS 的住宅價格（約 0.3 MB）、內政部不動產資訊平台的住宅價格指數與房價負擔能力指標（API，有時要等幾十秒）、主計總處的消費者物價（XML 約 27 MB），之後用快取約 10 秒。

`cities` 是城市主題：從 JRC 下載 GHSL Urban Centre Database 2025（一般屬性 6.6 MB、多時期城市 35 MB）與各國依城鄉程度的人口（1.5 MB），向 Wikidata 查人口 3 萬以上的地點（兩次查詢約 1 分鐘）與城市的中文名稱（約 130 次查詢），再向內政部戶政司的開放資料 API 查各村里人口（4 次）；第一次約 2.5 分鐘，之後用快取約 3 秒。

`vaccination` 是疫苗與防疫主題：向 WHO GHO 查 5 個疫苗涵蓋率指標（各約 3 MB）、世界銀行的 2 個序列，下載 Our World in Data 的 COVID-19 資料（compact.csv，約 180 MB）、OWID 封存的 JHU 累計死亡（1.6 MB）與 The Economist 超額死亡模型的兩個輸出檔（約 11 MB，固定在 2024-06-18 的 commit），衛福部死因統計跟 `disease` 共用快取；第一次約 1 分鐘，之後約 15 秒。台灣的常規疫苗完成率是照疾管署各年 PDF 的圖抄進 `pipeline/sources/cdc_tw.py` 的，每年 PDF 出新版時要補一年。

`height` 是平均身高主題：從 NCD-RisC 下載成人身高（2.4 MB）與兒童青少年身高（4.6 MB 的 zip）。NCD-RisC 的伺服器常回 HTTP 421 或傳到一半斷線，Python 的連線也常被重設，所以用 curl 下載、依 Content-Length 檢查大小並續傳（要有 curl，Windows 10 以後內建）；WPP 的年齡別人口跟其他主題共用快取。第一次約 1 分鐘，之後約 10 秒。台灣對照用的國健署實測數字是照成果報告的表抄進 `pipeline/sources/nahsit.py` 的，報告出新版時要手動更新。

`blood-types` 是血型分布主題：讀英文維基百科「Blood type distribution by country」固定版本的 wikitext（約 86 KB，不到 1 秒）；要更新就換 `pipeline/sources/wiki_blood_types.py` 的 `REVISION`。

`taxes` 是稅率主題：向 OECD 的 SDMX API 下載公司稅、個人所得稅最高稅率與勞動稅負（3 個 CSV，共約 16 MB），約 10 秒；加值型營業稅的標準稅率與台灣的稅率、級距、扣除額寫在 `pipeline/sources/oecd_tax.py`、`tw_tax_law.py`（出處見 DESIGN.md 第 8 節第 72 點），台灣的平均薪資用主計總處（跟薪資與工時主題同一個快取）。

`chain-stores` 是便利商店與連鎖品牌主題：向 OpenStreetMap 的 Overpass API 發 27 個查詢（9 個品牌的 `brand:wikidata` 各一個、沒有標 QID 的店依名稱比對 6 種店型各一個、所有便利商店分 12 個經度帶），一次一個、只要 9 個欄位的 CSV，共約 72 MB；公用伺服器忙的時候常回 502，會等一下再試（30 秒起加倍），2026-10-26 全部跑完約 2.5 小時。結果存在快取，之後約 1 分鐘（約 95 萬個點判斷國家）。公司公布的店數寫在 `pipeline/sources/chain_official.py`（出處見 DESIGN.md 第 8 節第 75 點），有新的年報時手動更新。要先有 `geo` 的國界。

`shipping` 是航運與港口主題：下載 UNCTAD Data Hub 的 6 個整包檔（7z 壓縮的 CSV，共約 2.5 MB，用 `py7zr` 解開，`pipeline/requirements.txt` 已列）、NGA 的 World Port Index（3.5 MB，NGA 的 CDN 常隨機回 503，會等一下再試）與臺灣港務公司的貨櫃裝卸量，約 5 秒。主要港口自己公布的吞吐量寫在 `pipeline/sources/port_teu.py`（出處見 DESIGN.md 第 8 節第 76 點），台灣四港會跟臺灣港務公司的開放資料比對，對不上時報錯。`shipping-density-tiles` 產生航運密度的約 5 km 網格圖磚（`public/tiles/ship-density/`，234 張、約 4.4 MB，部署時產生）：第一次下載世界銀行的 Global Shipping Traffic Density（535 MB），先解壓成 9.8 GB 的 GeoTIFF（讀完就刪）再平均成 0.02°（本機約 2 分鐘，結果存在快取），之後約 12 秒。

`oceans` 是海洋與漁業主題：從 Marine Regions 公開的 WFS 下載第 12 版專屬經濟海域的屬性與界線（界線約 25 MB，約 2 分鐘；網站的下載頁要填表，WFS 不必）、FAO FishStat 的全球產量整包（約 6 MB 的 zip）、FAOSTAT 的土地利用（約 3 MB）與漁業署《漁業統計年報》的生產量報表（約 4 MB 的 zip，裡面的 ODS 用標準函式庫讀），之後用快取約 10 秒。FAO 的台灣捕撈量會跟漁業署的數字比對，相差超過 6% 時報錯；FAO 每年 3 月、漁業署每年年中出新版，要改 `pipeline/sources/fishstat.py`、`fa_tw.py` 的網址。重疊主張與共同管理區的處理見 DESIGN.md 第 8 節第 77 點。

`daylight` 是晝夜與季節主題：不下載新的東西，讀國家小檔案的首都（要先跑 `profiles`）、旅行實用快取的 Natural Earth populated places 與 tzdata 套件，輸出各國首都的經緯度與時區（`capitals.json`）和赤道、回歸線、極圈（`circles.json`），不到 1 秒；白天長度等指標在瀏覽器裡用 `src/lib/solar.ts`（NOAA Solar Calculator 的公式）算。首都、時區、公式與 NOAA 的核對見 DESIGN.md 第 8 節第 87 點。

`rivers` 是河流與流域主題：下載 HydroRIVERS v1.0 的全球 shapefile（544 MB，不必登入；解壓後 2.2 GB，存在 `.cache/hydrosheds/`）、Marine Regions 的 IHO 海域與 Global Oceans and Seas（WFS 的 GeoJSON，共約 460 MB，伺服器要先產生好幾分鐘才開始傳）、Natural Earth 的河流中心線（約 20 MB）與 Natural Earth 附的約 3,800 個 Wikidata 項目的中文名稱（約 80 批 wbgetentities）。第一次讀 .dbf、把海域畫成 0.025° 的網格約 12 分鐘（結果存在 `.cache/hydrosheds/`、`.cache/rivers/`），之後約 40 秒（847.8 萬段河道判斷國家、Natural Earth 的河名比對、簡化）。要先有 `geo` 的國界。授權（HydroSHEDS 授權協議，衍生檔只能當成地圖的一部分提供）、海與大洋的分法、河名的比對見 DESIGN.md 第 8 節第 12、86 點。

`dams` 是河流與流域主題的水壩與水庫（輸出到 `public/data/topics/rivers/`，不必先跑 `rivers`）：下載 Global Dam Watch v1.0（figshare，70 MB）、水利署的水庫基本資料（data.gov.tw，10 KB）與 Wikidata 的台灣水庫座標，約 20 秒；台灣水庫的完工年份是從水利署網站整理的表（`pipeline/sources/wra_reservoirs.py`）。要先有 `geo` 的國界。授權與做法見 DESIGN.md 第 8 節第 12、96 點。

`antipodes` 是地球的另一邊（對蹠點）主題：用地圖本身的 1:50m 國界（`geo`）把每個國家翻到對蹠點、跟陸地相交（shapely，`pipeline/requirements.txt`），全球每 3 km 一點的等面積網格（約 5,700 萬點）判斷每一點與它的對蹠點各在哪一國（`geoindex` 的 Natural Earth 1:10m）或哪一片海（河流主題的 IHO 海域網格 `.cache/rivers/sea_rasters_0025.npz`，沒有的話會下載 Marine Regions 的 IHO 海域與 Global Oceans and Seas，畫成網格約 5 分鐘），首都讀晝夜與季節主題的 `capitals.json`（要先跑 `daylight`），最近的城鎮用旅行實用快取的 Natural Earth populated places；之後約 30 秒。輸出翻過去的陸地（`flipped.json`）、前端查海名的 0.25° 網格（`seas.json`）、指標與側欄。方法、抽查與授權見 DESIGN.md 第 8 節第 12、89 點。

`long-run` 是人口、人均收入、健康三個主題的「1800 年起」指標：從 GitHub 的 Gapminder fasttrack（固定的 commit，CC BY 4.0）下載人口、人均 GDP、平均壽命與世界合計（6 個 CSV，約 3 MB），只取到最近的實際年份，約 2 秒。來源、授權與年份範圍見 DESIGN.md 第 8 節第 12、98 點。

`magnetic` 是北磁極的漂移與磁偏角主題：下載 NOAA NCEI 的磁極位置（`NP.xy`、`SP.xy`，各 10 KB）與 World Magnetic Model 2025 的係數（43 KB 的 zip，含官方測試值），用測試值驗證自己寫的 WMM 計算（`pipeline/sources/wmm.py`），算 0.5° 網格的磁偏角、用 contourpy（`pipeline/requirements.txt`）畫等偏角線與指南針不可靠的範圍；首都讀晝夜與季節主題的 `capitals.json`（要先跑 `daylight`）。約 2 秒。方法與授權見 DESIGN.md 第 8 節第 12、101 點。

`aurora` 是此刻的極光主題：極光預報（NOAA SWPC 的 OVATION）由瀏覽器即時讀，pipeline 只算各國的國土碰到哪些經緯度 1° 格點（Natural Earth 1:10m，南、北緯 35° 以外）與首都最近的格點（讀晝夜與季節主題的 `capitals.json`，要先跑 `daylight`），輸出 `cells.json`（41 KB）。約 10 秒。方法與授權見 DESIGN.md 第 8 節第 12、102 點。

`logbooks` 是大航海時代的航海日誌主題：下載 CLIWOC 2.1 的 IMMA 原始檔（PANGAEA，29 MB，解開 2.46 GB，串流讀），依日誌、船與出發地、目的地分成航程，拿掉跳點，在間隔超過 10 天、距離不合理或直線深入陸地 30 公里以上的地方斷開（陸地與海用河流主題的 IHO 海域網格，`sources/sea_areas.py`，第一次要下載 Marine Regions 的海域），輸出 `tracks.json`（1.77 MB）、各國每年的船數 `ships.json` 與側欄的 `panel.json`（經過各國附近 100 公里內的航程）。約 30 秒。方法與授權見 DESIGN.md 第 8 節第 12、103 點。

`koppen` 是氣候分區（柯本）主題：下載 Beck 等人 2023 的柯本－蓋格分類圖（figshare，130 MB），把 8 個時期（4 個歷史時期，加上 2041–2070、2071–2099 年的 SSP2-4.5 與 SSP5-8.5）的 0.1° 網格各存成一張 8 位元灰階 PNG（像素值就是類型代碼，共 1.25 MB），陸地格子歸到國家（Natural Earth 1:10m）算各國每個時期的類型面積比例，輸出面積最大的類型與氣候帶、跟 1991–2020 年不同的面積比例與側欄的 `panel.json`。約 15 秒。方法與授權見 DESIGN.md 第 8 節第 12、104 點。

`ice` 是冰河、海冰與海平面主題：下載 WGMS AMCE（54 MB，每條冰河每年的質量變化，依中心點歸國算面積加權的累計變化）、NSIDC 海冰指數北極 9 月與南極 2 月的邊緣線（約 200 個小 shapefile，自己讀 .shp、用 rasterio 的 PROJ 換成經緯度並抹平鋸齒）與 NOAA STAR 的海平面趨勢網格（分 7 級存成 PNG，沿海 200 公里內的平均用颱風主題的 NearIndex），輸出 `glacier-thinning.json`、`glacier-gt.json`、`ice-edges.json`、`sea-level.json`、`grid/sea-level.png` 與 `panel.json`。約 15 秒（第一次下載約 1 分鐘）。方法與授權見 DESIGN.md 第 8 節第 12、105 點。

`reads` 是各國在讀什麼主題：一天一天下載 Wikimedia 的差分隱私每日瀏覽量（country_project_page，最近 24 個完整的月份共 730 個檔、約 13 GB，串流讀、不留原檔，每月的彙整存在 `.cache/wikimedia/months/`），每國每月留前 10 名，名稱用 Wikidata 的 SPARQL 查詢服務查中文與英文（一次 400 個，快取在 `.cache/wikimedia/labels.json`），輸出 `top.json`（地圖上的第一名）、`countries/<ISO3>.json`（側欄的前 10 名）、`top-views.json` 與 `english.json`。第一次約 35 分鐘，之後只下載新的月份。方法與授權見 DESIGN.md 第 8 節第 12、106 點。

`empires` 是帝國與疆界主題：下載 Cliopatria v0.2.1（Zenodo，299 MB）與 COLDAT（Harvard Dataverse，26 KB），取樣 119 個年份的政體範圍（西元前每 100 年、1800 年以前每 50 年、之後每 5 年），依史實修正台灣的部分（`FIXES`，模組開頭逐條寫），簡化後輸出 `polities.json`（範圍）、`labels.json`（名稱的位置）、`countries.json`（今天的國土歷代屬於誰）、`colonizer.json` 與 `colonial.json`（殖民）。政體的中文名稱用 Wikidata（跟 `reads` 共用快取），只在英文名稱對得上時用，另有自己寫的 `ZH_NAMES`。約 1 分鐘（第一次下載約 2 分鐘）。方法與授權見 DESIGN.md 第 8 節第 12、107 點。

`plates` 是板塊漂移主題：下載 Merdith 等 2021 的板塊模型 v1.2.4（Zenodo），用 pyGPlates（`pip install pygplates`，GPL-2.0，只在建置時用）把今天的國界（1:50m）切到各板塊上，轉回 0–250 百萬年前每 500 萬年一個時間點，輸出 `countries/<年份>.json`（年份是負的百萬年，0 是今天）、`boundaries/<年份>.json`（那時的板塊邊界）與 `paleolat.json`（各國國土那時的緯度）。約 1.5 分鐘。方法與授權見 DESIGN.md 第 8 節第 12、108 點。

`wind` 是風與季風主題：從 NOAA PSL 的 THREDDS 下載 NCEP/NCAR 再分析離地 10 公尺的 uwnd、vwnd、wspd 每月長期平均（1991–2020，3 個約 1 MB 的 netCDF），輸出 `field/<月>.json`（2° 的風場，給粒子動畫）、`grid/<月>.png`（風速分 6 級的 1° 網格）、`speed.json`（各國國土的平均風速）與 `panel.json`（各國每個月的風向、穩定度與風速）。約 10 秒。方法與授權見 DESIGN.md 第 8 節第 12、109 點。

`eclipses` 是日食路徑主題：從 NASA 日食網站（eclipse.gsfc.nasa.gov）下載五千年日食目錄的 3 頁（1801–2100 年）與每一次日全食、日環食、混合食的貝塞爾根數頁（路徑表那一組 SEbeselm 有的用它，沒有的用五千年日食典的 SEdata；共約 600 頁、5 MB，每頁間隔 0.3 秒，第一次約 10 分鐘，存在 `.cache/nasa-eclipse/`），自己算每一次日食的路徑與經過的國家（約 300 次、每次約 1 秒）。要先有 `geo` 的國界與河流主題的海域網格（`.cache/rivers/sea_rasters_0025.npz`，食甚在海上時寫哪一片海）。算法、跟 NASA 路徑表的比對與授權（公有領域，要寫「Eclipse Predictions by Fred Espenak, NASA's GSFC」）見 DESIGN.md 第 8 節第 12、88 點。

`lunar` 是日食與月食主題的月食（輸出到 `public/data/topics/eclipses/`，不必先跑 `eclipses`）：下載 NASA 五千年月食目錄的 3 頁（LEcat5，1801–2100 年，約 240 KB，跟日食同一個快取資料夾），算每一次月全食、月偏食看得到的範圍與各國首都看不看得到，不到 10 秒。要先跑 `daylight`（首都的位置與時區，`public/data/topics/daylight/capitals.json`）。做法與授權（要寫「Eclipse Predictions by Fred Espenak and Jean Meeus (NASA's GSFC)」）見 DESIGN.md 第 8 節第 12、99 點。

`plastic` 是塑膠污染主題：下載 Cottom 等人（2024）的 SPOT 模型輸出（Dryad 擋程式下載，改用 Our World in Data 快照庫的同一批檔，4 MB，核對 md5）、Meijer 等人（2021）的河口 shapefile（figshare，0.7 MB）、BACI 的 HS92 版（2.4 GB，跟貿易主題的 HS17 版不同檔，第一次下載約 7 分鐘），讀 HS 3915 約 2 分鐘；另外查環境部開放資料平台的一般廢棄物與資源回收（3 個資料集）與財政部的 HS 3915 進出口值。河口依位置判斷國家，要先有 `geo` 的國界；跟論文的國家表差超過 15% 時報錯。來源與授權見 DESIGN.md 第 8 節第 78 點。

`internet-speed` 是網路速度主題：用 `pyarrow`（`pipeline/requirements.txt` 已列）從 Ookla 公開的 S3 bucket（不必帳號）讀 2019–2026 年每年第 3 季固網與行動的 parquet，只讀 6 個欄位（共約 1.4 GB，約 3 分鐘，存在 `.cache/ookla/`）；約 2,000 萬個圖塊依位置判斷國家，第一次約 10 分鐘（要先有 `geo` 的國界，結果存在快取），之後約 2 分鐘。台灣的對照另外下載數位發展部的 5G 量測（CC0，兩個小 CSV）。Ookla 每季更新，新的一年改 `pipeline/topics/internet_speed.py` 的 `YEARS`；某個國家的測試突然少了九成以上（Ookla 2026 年拿掉了俄羅斯、伊朗等）會報錯，要人工確認。`internet-speed-tiles` 產生下載速度的約 2 km 網格圖磚（`public/tiles/internet-speed-fixed/`、`internet-speed-mobile/`，最新一季，805 張、約 3.1 MB，部署時產生），約 20 秒。來源、授權（CC BY-NC-SA 4.0）與方法見 DESIGN.md 第 8 節第 79 點。

`developers` 是開發者與開源主題：從 raw.githubusercontent.com 下載 GitHub Innovation Graph 的 7 個 CSV 與 2 個補充資料（共約 8 MB，不經 GitHub API，所以沒有次數限制），約 2 秒；人口用 WPP 2024（跟人口主題共用快取）。Innovation Graph 每季更新，要更新加 `--refresh`。`EU`（歐盟 27 國的合計）跟會員國相加對不上、或頁尾寫的 VPN 倍數變了，會報錯。

`profiles` 是國家小檔案主題：向 Wikidata 的查詢服務發 6 個 SPARQL 查詢（每個 2–5 秒）、用 wbgetentities 查約 40 批名稱，下載 FAOSTAT 的土地利用（陸地面積，約 3 MB），不用帳號、不用金鑰，全部約 1 分鐘（之後用快取約 3 秒）；要先有 `geo` 的國界，也讀人口、旅行實用、語言、民主與自由、城市、海拔、國際組織、台灣的外交已經產生的資料檔（那些主題重跑後這裡也要重跑）。元首與政府首長常常改，要更新加 `--refresh`。台灣的首都、總統、行政院長、貨幣、區號、網域每次跟預期核對，對不上會印出來（不蓋掉 Wikidata 的值）；政體形式跟 Wikidata 不同而沒有寫理由、內陸國或幾個國家的鄰國數跟預期不同，會報錯。見 DESIGN.md 第 8 節第 82 點。

`skyscrapers` 是摩天大樓主題：向 Wikidata 的查詢服務發 7 個 SPARQL 查詢（150 m 以上的候選、所在行政區往上 4 層、城市類別、國家代碼，每個幾秒），用 wbgetentities 取約 25 批大樓的完整陳述與約 20 批行政區的名稱，不用帳號、不用金鑰，第一次約 1 分鐘（之後用快取不到 1 秒）；要先有 `geo` 的國界，也讀城市主題的 `cities.json`（P131 找不到城市的大樓用 GHSL 的城市名稱）。跑完要重跑 `profiles`（小檔案的「最高的大樓」讀它的 `buildings.json`）。逐一看過的修正（不算的、高度、完工年份、重複、城市）寫在 `pipeline/topics/skyscrapers.py` 開頭的表，每一個寫理由；跟 CTBUH 總數比的涵蓋率會跟 `src/topics/skyscrapers.ts` 寫的百分比核對，不一樣就報錯。Wikidata 一直在改，要更新加 `--refresh`，更新後要再看一次印出來的「每層高度」與 300 m 以上的清單。見 DESIGN.md 第 8 節第 83 點。

`flags` 是國旗主題：向 Wikidata 的查詢服務發 2 個 SPARQL 查詢（各國的國旗圖檔與國旗項目、國旗項目的成立時間、描繪內容、長寬比），用 Commons 的 API 查約 5 批檔案資訊（含授權），從 upload.wikimedia.org 下載約 230 個國旗 SVG（共約 3.8 MB，存在 `.cache/commons/flags/`，依 sha1 核對），不用帳號、不用金鑰，第一次約 2 分鐘（之後約 1 分鐘，大多是點陣化與比對）。要先有 `geo` 的國界，也要先 `npm install`：SVG 用 node 的 svgo（devDependency，`pipeline/svgo.mjs`）最佳化，畫出來跟原檔比對過才採用；點陣化用 `resvg-py`、`Pillow`，scour 是備援（`pipeline/requirements.txt` 已列）。授權只收公有領域、CC0 與阿曼的政府開放授權，其他的會報錯；每個檔的出處、授權、作者寫在 `public/data/topics/flags/svg/CREDITS.txt`。逐一看過的表（指定的圖檔、圖案、旗幟家族、採用年份、顏色的例外）寫在 `pipeline/topics/flags.py` 開頭，每一條寫理由；圖案跟 Wikidata 不同、採用年份對不上而沒寫理由的會報錯。見 DESIGN.md 第 8 節第 84 點。

`publications` 是學術論文主題：向 OpenAlex 的 API 查 `group_by` 的彙總（約 320 次查詢、第一次約 5 分鐘，存在 `.cache/openalex/`），不逐篇下載、不用 API 金鑰；沒有金鑰時同一個 IP 一天約可以查 1,000 次（UTC 0 點重算），額度用完會報錯，隔天再跑會接著查。人口用 WPP 2024（跟人口主題共用快取）。OpenAlex 每天更新，要更新加 `--refresh`。來源、授權（CC0）與算法（只算 CWTS 核心來源、整數計數）見 DESIGN.md 第 8 節第 81 點。

`governance` 是政府治理主題：向世界銀行 API 查 WGI 六個面向各 6 個序列（分數、信賴區間上下限、估計值、標準誤、來源數，36 次查詢、共約 52 MB），第一次約 1 分鐘，之後用快取約 1 秒；法治的序列跟 `crime` 共用快取。WGI 每年 9 月改版，要更新加 `--refresh`。

`pisa` 是學生能力主題：從 OECD 的 StatLink 下載《PISA 2025 Results (Volume I)》附錄的兩個 Excel（約 2.8 MB），約 1 秒；臺灣的分數會跟臺灣 PISA 國家研究中心公布的數字比對，對不上時會報錯。

`marriage` 是婚姻與家庭主題：下載聯合國 World Marriage Data 2019（約 26 MB）、Eurostat 的 4 個資料集、OECD Family Database 的 2 個 Excel、內政部戶政司的 5 個歷年統計表與內政部統計查詢網的婚姻狀況，再從 UNdata 一國一頁抓結婚、離婚對數（第一次約 220 頁網頁，每頁間隔 0.3 秒，約 4 分鐘；UNdata 舊的下載介面已經停用，見 DESIGN.md 第 8 節第 69 點），之後用快取約 45 秒。同性伴侶的法律地位是 `pipeline/sources/same_sex_unions.py` 依維基百科整理的表，有國家修法時改這個檔。

`laws` 是法律與制度主題：死刑與法定年齡是依英文維基百科自行整理的表（`pipeline/sources/death_penalty.py`、`legal_ages.py`，檔頭列出每一篇條目的 revid），不必下載，不到 1 秒；資料檔依 CC BY-SA 4.0 分享。

`aid` 是國際援助與僑匯主題：向 OECD 的 SDMX API 下載 DAC1（各援助國的 ODA、占 GNI 與組成）與 DAC2A（援助國 × 受援國的 ODA，1960 年起，含多邊機構；3 個 CSV 共約 75 MB），向世界銀行 API 查 3 個僑匯序列，台灣讀中央銀行的國際收支（跟 `tourism`、`reserves` 共用快取）；第一次約 30 秒，之後用快取約 3 秒。DAC 每年 4 月公布前一年的初步數字、12 月公布完整的數字，更新時加 `--refresh`。

`china-lending` 是中國的海外貸款主題：下載 AidData 的 Global Chinese Development Finance Dataset 3.0（zip 28.6 MB，xlsx 讀一次約 15 秒，之後用快取不到 1 秒），GDP 與人口讀人均收入、人口主題已經產生的指標檔（要先跑 `income`、`population`）。

國際的四個主題：`passport` 只下載一個約 690 KB 的 CSV（Passport Index 資料集，固定在 GitHub 上的某個 commit），幾秒就跑完；要換新版改 `pipeline/sources/passport_index.py` 的 `COMMIT` 與 `DATA_DATE`（`src/topics/passport.ts` 的 `DATA_DATE` 也要改，資料管線會檢查），台灣護照跟領事事務局名單的比對要先有 `taiwan-diplomacy` 的資料。`organizations` 不用下載：16 個國際組織的成員表是 `pipeline/sources/igo_members.py` 依各組織官網整理的，組織有新成員、退出或暫停時改這個檔（`CHECK_COUNTS` 的成員數也要跟著改，對不上時會報錯）；今年的狀態是跑資料管線當天的，跨年後重跑一次，時間軸才會多一年。`un-votes` 第一次會從 Harvard Dataverse 下載約 23 MB（一致度的 RData 21.7 MB、理想點的 CSV 1.4 MB），整個步驟約半分鐘。`conflict` 第一次會從 UCDP 下載約 40 MB（GED 的事件資料），之後約 25 秒。

指標檔輸出時數值會壓縮（格式見 DESIGN.md 第 3 節）。`compact` 把還沒壓縮的舊指標檔一次轉換，不需要重新下載，重複執行沒有影響。

下載的原始檔會快取在 `pipeline/.cache/`，這個資料夾不進版本控制。第一次跑全部大約要下載 3.3 GB（主要是 FAOSTAT 的貿易檔、雙邊貿易矩陣與糧食平衡表、CEPII BACI、GMTED2010 的 DEM、GHS-POP 的網格人口和 Anthropic Economic Index），世界銀行 API 比較慢，全部跑完約 30 分鐘，其中 `trade` 要讀 8.5 GB 的 FAOSTAT 雙邊貿易矩陣，約占一半。`population-density-tiles` 另外要下載其他 11 期 GHS-POP（約 5.3 GB），再多約 25 分鐘。`semiconductors` 跟 `trade` 共用 BACI 的快取（讀一次約 2 分鐘），`minerals` 第一次會下載 USGS MCS 2020–2026 版各礦種章節的 PDF（約 110 個、36 MB）。

## 建置

```bash
npm run build
```

輸出在 `dist/`，可以放到任何靜態主機。

Service worker（離線、快取）只在建置後的版本運作。要在本機試，執行：

```bash
npm run preview
```

## 部署

推送到 `main` 後，GitHub Actions（`.github/workflows/deploy.yml`）會自動建置並發佈到 GitHub Pages，約 1–2 分鐘。
資料檔已經在版本庫裡，所以更新資料的流程是：本機執行 `npm run data`，再把 `public/data/` 的變更提交、推送。

例外是人口密度的 1 km 網格圖磚：部署流程自己產生，存在 GitHub Actions 的快取裡。產生的程式或地圖的橘色色階改了（或快取超過 7 天沒用到被清掉）才重新產生，那一次部署約多 15 分鐘；JRC 的伺服器連不上時照樣部署，用上一版的圖磚。暖化的 0.5° 網格圖磚也一樣（另一個快取，產生約 5 分鐘，CRU 的伺服器連不上時用上一版），太陽能與風能的約 2 km 網格圖磚也是（再一個快取，產生約 3 分鐘），夜間燈光的約 500 m 網格圖磚也是（再一個快取，從 Zenodo 下載 4 年約 270 MB 再產生，第一次部署約 3.5 分鐘，Zenodo 連不上時用上一版），航運密度的約 5 km 網格圖磚也是（再一個快取，從世界銀行下載 535 MB、解壓再產生，約 1.5 分鐘，連不上時用上一版），網路速度的約 2 km 網格圖磚也是（再一個快取，從 Ookla 的 S3 bucket 只讀最新一季的 6 個欄位，約 1 分鐘，連不上時用上一版）。

- **Map**: switch between globe and flat map, zoom down to street level, and choose from five basemaps. **3D** turns values into heights (or real terrain on the elevation topic). Click a country to open its panel with rankings, time series and topic details. Every map also has a **Ranking** table view.
- **Search**: type a country name in English or Chinese, a common alias (UK, USA, Korea) or an ISO code (TW, TWN). Partial names and small typos work too.
- **Keyboard shortcuts** (press `?`): `/` search, `←` `→` change year, Space play/pause, `+` `−` zoom, `Esc` clear the selection.
- **Share**: download the current map as a PNG (with title, legend and sources), download the indicator as CSV, or copy a link. The whole view, including the language (`lang=en`), is stored in the URL.
- **Area estimate**: on the population topic, draw a box on the map to estimate how many people live inside it.
- **1 km grid**: population density can switch from country averages to a grid of cells about 1 km across (JRC GHS-POP, every 5 years from 1975 to 2030, following the time slider). Warming (on the temperature topic) can likewise switch to a 0.5° grid (CRU TS, one map per year), solar and wind potential to a ~2 km grid (Global Solar Atlas, Global Wind Atlas), and download speed to a ~2 km grid of Speedtest by Ookla tests (the latest quarter). Night lights open on a ~500 m grid (EOG annual VIIRS composites for 2013, 2016, 2020 and 2024) drawn over a dark night backdrop, so it reads as a night view on any basemap. The grid tiles are not in the repository; the deploy workflow builds and caches them.
